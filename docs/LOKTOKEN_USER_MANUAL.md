# LokToken 从零到一使用手册

版本：v1.0
适用对象：LokToken 用户、企业运营人员、审计人员、发布验收人员，以及通过 OIDC/SSO 接入的第三方应用用户

本手册以“一个新用户完成首次模型调用”为主线，同时覆盖 LokToken 管理控制台和用户中心的全部主要功能。它既是操作说明，也是商用验收清单。文中“可用”表示当前代码已经实现并通过本地/UAT 验证；“配置后可用”表示还需要真实供应商、域名或支付环境；“暂不可商用”表示当前仅有目录或占位能力。

## 1. 产品边界

LokToken 是独立的模型网关和额度运营平台，为个人、团队和第三方应用提供统一模型目录、统一 API、额度、Key、请求记录和订单/福利能力。

### 当前可以做什么

- 通过账号密码、试用入口或可选的 OIDC/SSO 登录进入用户中心。
- 在模型广场查看公开模型、模型类型、价格、渠道健康状态和调用示例。
- 创建、停用、轮换 API Key，并设置有效期和消费上限。
- 使用兑换码或充值申请获得额度。
- 通过 OpenAI-compatible `/v1/chat/completions` 调用已上架模型，支持同步和 SSE 流式响应。
- 查看请求、Token、费用、Trace ID、错误信息和账户流水。
- 管理员配置模型、供应商渠道、账户、订单、福利和审计记录。

### 当前边界

- 新注册账户默认余额为 0，不会自动赠送可消费额度。
- 真实在线支付尚未接入，订单确认/退款目前用于人工运营或联调流程。
- 图像、视频模型可进入候选目录，但在对应统一调用适配器和计费规则完成前不得上架为可调用模型。
- LokSystem 本机桌面 SSO 仅用于桌面联调；生产环境应使用 HTTPS OIDC。
- LokToken 保存调用元数据和计费结果，不保存模型输入/输出正文。

## 2. 角色与入口

| 角色 | 入口 | 主要职责 | 不应拥有的能力 |
|---|---|---|---|
| 超级管理员 | `/` | 管理管理员账号、模型预检、全量运营和审计 | 无 |
| 运营人员 | `/` | 模型渠道、账户、Key、额度、订单、福利和用量运营 | 管理管理员账号、超级管理员专属预检/高风险操作 |
| 审计员 | `/` | 查看模型、账户、订单、用量和安全审计 | 所有新增、修改、停用、确认、退款和发放操作 |
| 普通用户 | `/portal` | 选择模型、获取额度、创建 Key、调用和查看记录 | 管理其他账户或供应商密钥 |
| 外部身份用户 | OIDC/SSO 跳转 | 通过配置的身份提供商登录并复用 LokToken 账户 | 不应重复绑定同一身份 |

生产环境必须使用 HTTPS、独立随机密钥、PostgreSQL、Alembic 迁移、真实供应商渠道、Redis 共享限流和网关层限流。

## 3. 新用户完整路径

```text
进入用户中心
  -> 注册/登录或 LokSystem 登录
  -> 查看模型广场和价格
  -> 兑换福利或提交额度申请
  -> 创建 API Key
  -> 调用已上架模型
  -> 查看请求记录、费用和余额
  -> Key 轮换、额度补充和持续运营
```

### 3.1 进入用户中心

打开 `https://<TOKEN域名>/portal`。登录页提供三种方式：

1. **账号登录**：输入用户名和密码。
2. **注册账号**：填写用户名、显示名称、安全联系方式和至少 8 位密码，注册后完成一次性验证码验证。
3. **试用入口**：粘贴管理员发放的 `trl_` 试用令牌；试用入口仅用于创建和使用当前试用链接下的 Key，不提供组织、账户安全、充值或兑换操作；试用 Key 的有效期不超过试用到期时间。

也可以点击 **LokSystem 一键注册 / 登录**。生产环境会跳转到 LokSystem OIDC，通过授权码 + PKCE 返回；首次登录可按稳定的 LokSystem 用户 ID 自动创建 LokToken 账户。

登录成功后检查：

- 浏览器地址中不再保留试用令牌。
- 右上角显示当前账户和工作空间。
- 用户中心导航完整显示：用户概览、模型广场、额度管理、API管理、请求记录、订单管理、兑换福利。
- 退出后受保护页面不能继续访问。

注册时还需要填写邮箱或手机号作为安全联系方式，并使用一次性验证码完成验证。只有已验证的联系方式才能接收密码重置凭证；未验证、已停用或不存在的账号发起重置时，页面只返回统一受理提示，不泄露账号状态。

### 3.2 获取额度

新用户余额为 0 时，先进入 **兑换福利** 或 **额度管理**。

#### 兑换福利

1. 打开 **兑换福利**。
2. 输入运营人员发放的兑换码。
3. 确认额度、有效期和活动说明。
4. 提交后检查余额是否即时增加。
5. 在兑换历史和账户流水中确认一条独立记录。

同一码不可重复领取；过期、超过总领取次数或已被当前账户领取时，应显示明确错误，不产生余额变动。

#### 额度管理/充值申请

1. 打开 **额度管理**，查看当前余额、累计消费和流水。
2. 选择充值金额并创建申请。
3. 在 **订单管理** 查看订单号、金额和状态。
4. 人工确认后状态变为“已入账”，余额和流水同步增加。

当前人工确认不等同于真实支付。上线前必须接入支付渠道、验签、异步通知、幂等和对账流程。

### 3.3 选择模型

打开 **模型广场**：

- 按文本、推理、代码、视觉、工具调用等能力筛选。
- 查看公开模型 ID、服务商、上下文长度、输入/输出价格、限流和健康状态。
- 优先选择“渠道健康”且状态为“已上架”的模型。
- 复制 cURL 或 Python 示例，模型名必须使用页面展示的公开模型 ID。

价格按人民币“元 / 1M Token”展示。平台内部以微元/1K Token 结算，用户不应自行换算接口费用。

### 3.4 创建 API Key

1. 打开 **API管理**。
2. 点击 **创建 Key**。
3. 填写名称、有效天数和累计消费上限。
4. 创建后立即复制完整 Key，并存放在密码管理器或服务端密钥管理系统。
5. 页面后续只显示 Key 前缀，不会再次显示完整密钥。

Key 和用户会话令牌用途不同：

- `usr_...` / `trl_...`：只用于用户中心会话。
- `tok_...`：用于 `/v1` 模型调用。

发生泄露、人员变更或应用迁移时，在 API 管理中执行 **轮换**：先生成新 Key，再停用旧 Key，并验证新 Key 调用成功。

### 3.5 发起第一次调用

用户中心显示 Base URL，例如 `https://<TOKEN域名>/v1`。示例：

```bash
curl https://<TOKEN域名>/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4-flash","messages":[{"role":"user","content":"你好，请介绍 LokToken"}]}'
```

流式调用：

```bash
curl -N https://<TOKEN域名>/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4-flash","messages":[{"role":"user","content":"请分点介绍"}],"stream":true}'
```

调用前平台会预扣额度，成功后按供应商真实 usage 结算并退回差额；供应商失败、超时或渠道切换失败时释放预扣。一次请求应有唯一 request ID 和 trace ID。

### 3.6 查看请求记录

进入 **请求记录**，按时间、模型、Key、状态或请求 ID 筛选。详情至少应包含：

- 请求 ID、Trace ID、创建时间和耗时。
- 模型公开 ID、输入 Token、输出 Token、总 Token。
- 平台费用、状态、错误码和错误信息。
- 使用的 Key 前缀和工作空间。

记录不应展示 API Key 明文、完整请求正文或模型输出。支持导出时，文件应只包含当前账户数据。

### 3.7 订单和退款

用户在 **订单管理** 查看充值申请、状态、金额、创建时间、入账时间和退款时间。

状态流转：

```text
pending -> paid -> refunded
pending -> rejected
```

只有已入账订单可以退款；重复确认、重复退款、金额不一致和不存在订单必须拒绝且不产生重复流水。退款后余额、订单和账本必须一致。

## 4. 用户中心功能验收

### 用户概览

检查账户余额、有效 Key、累计请求、Base URL、周期费用、Token/费用/请求趋势、模型排行和活动热力图是否与请求记录一致。切换 7/30/90 天、模型和 Key 后，统计范围必须同步变化。

### 模型广场

检查模型卡片字段完整、价格单位明确、已上架与候选状态区分、健康状态可解释、调用示例可复制。候选模型不得出现在用户可调用列表。

### 额度管理

检查余额、流水、额度来源、时间、幂等键和失败原因可追溯。余额不足调用必须返回 `402` 和 `insufficient_balance`，不能产生负余额。

### API管理

检查创建只展示一次、前缀脱敏、有效期、消费上限、最近使用、停用和轮换。旧 Key 停用后必须立即返回 401。

### 请求记录

检查同步、流式、失败、超时、重试、重复请求和渠道切换记录。费用必须与账本和供应商 usage 对得上。

### 订单管理

检查订单状态、人工确认、拒绝、退款、幂等、余额和流水一致性。

### 兑换福利

检查兑换码创建一次性明文、哈希存储、过期、次数限制、重复领取和兑换流水。

### 账号安全

检查密码重置、旧密码失效、绑定安全联系方式、退出其他会话、Key 轮换和安全事件提示。生产环境不得在页面回显重置凭证。

## 5. 管理控制台完整路径

管理员打开 `/`，使用管理员账号登录。首次初始化仅使用一次 `TOKEN_ADMIN_TOKEN`，之后全部使用管理员账号和 Bearer 会话。

### 5.1 管理概览

查看账户余额、累计请求、累计 Token、累计消费和最近调用。验收时将概览数字与用量记录、账户流水和账本对照，不能只验证页面有数据。

### 5.2 模型管理

模型管理是平台正式上架入口：

1. 使用预置目录或 **批量接入** 读取上游 OpenAI-compatible `/models`。
2. 批量接入中的默认输入/输出售价只是没有官方参考价时的可选兜底值，不是整家供应商的统一价格；不同模型必须在模型列表的“定价”入口单独核对并保存最终售价。
3. 有官方价格的模型可在“定价”中选择按利润率自动定价。系统使用官方未命中缓存、低峰输入价和官方输出价，按 `平台售价 = 官方价格 ÷（1 - 利润率）` 计算；无官方价格的模型只能手工设置平台售价。
4. 确认公开模型名、上游模型名、模型类型和能力标签。
5. 配置供应商 API Key 环境变量名或通过控制台加密录入密钥。
6. 配置平台输入/输出价格，统一按元/1M Token展示。
5. 配置 Primary 和备用渠道的优先级、权重、超时和启停状态。
6. 执行单渠道检查或 **检测全部渠道**。
7. 执行预检，确认价格、渠道、适配器和计费规则完整。
8. 只有预检通过后才 **上架**，再到用户模型广场确认可见。

密钥明文不得进入浏览器、数据库日志或 Git。候选图像/视频模型在适配器和价格未完成前必须保持“待完善”。

### 5.3 账户管理

运营人员可以创建或停用 LokSystem 用户账户、查看名称、外部用户标识、余额和状态。当前产品优先通过 LokSystem 身份登录和绑定账户；底层也保留 OIDC、其他外部身份及独立 API 账户的扩展能力。余额调整必须填写原因、幂等键并生成账本流水；不得直接修改余额字段绕过流水。

### 5.4 API管理

管理员可查看 Key 所属账户、名称、前缀、状态、有效期、消费上限和最近使用时间。创建后的完整 Key 只返回一次；停用、轮换和批量操作必须写审计事件。

### 5.5 订单管理

处理充值申请、人工确认、拒绝、退款和对账。运营操作要遵守订单状态机，审计员只能查看。真实支付接入前，人工确认只允许在预发布或明确授权的运营流程使用。

### 5.6 福利管理

创建福利码时设置名称、额度、最大领取次数和失效时间。明文只在创建响应展示一次；日常列表只显示摘要、已领取次数、状态和有效期。

### 5.7 用量管理

按账户、模型、Key、状态、时间查看请求。重点关注失败率、Token、费用、渠道健康、重复请求、退款和异常账本。导出数据应脱敏并限制权限。

### 5.8 安全审计

审计事件至少覆盖登录、登出、管理员变更、模型/渠道变更、Key 操作、额度变动、订单确认/退款、福利创建/兑换和密码/会话安全操作。审计员能读不能写；日志不得包含密钥、兑换码明文或模型正文。

## 6. 商用验收场景

### P0：发布阻断项

- 用户注册、登录、登出、密码重置可完成，旧密码和旧会话立即失效。
- 管理员、运营、审计员权限在接口和页面双重生效。
- 真实模型同步和流式响应成功，Token 统计与供应商 usage 一致。
- 余额不足返回 402；超时、5xx、429、失败重试和渠道熔断不产生错误扣费。
- 订单确认、退款、福利兑换和余额流水幂等且可对账。
- API Key 仅展示一次，轮换后旧 Key 立即失效。
- 生产关闭 Mock、关闭自动建表、启用 HTTPS、PostgreSQL、备份和网关限流。

### P1：上线前必须验证

- LokSystem 生产 OIDC 授权码 + PKCE、账户绑定和首次自动开户。
- 桌面 `1440x1000`、移动 `390x844` 截图检查：无横向溢出、表格可滚动、弹窗不遮挡、按钮可点击。
- 多渠道主备切换、冷却恢复、流式已输出后不重放。
- 请求导出按账户隔离，审计和应用日志脱敏。
- 数据库迁移、备份恢复、健康检查、就绪检查和回滚演练。

### P2：运营优化项

- 用户中心通知中心：查看余额预警、Key 生命周期和账户安全事件，支持标记已读。
- 供应商成本逐笔对账和毛利报表。
- 余额预警、Key 即将过期通知、渠道异常通知。
- 企业团队空间、项目级额度、成员角色和渠道分发。
- 真实支付、发票、退款审批和财务对账。
- 观测平台接入 trace、指标、告警和运营看板。

## 7. 异常处理速查

| 现象 | 用户先检查 | 运营检查 |
|---|---|---|
| 登录失败 | 账号、密码、是否停用、是否需要重置 | 账户状态、密码重置事件、会话版本 |
| `401` | Key 是否完整、是否过期/停用 | Key 状态、轮换审计 |
| `402` | 余额和 Key 消费上限 | 账户流水、额度发放和订单状态 |
| 模型不可用 | 模型是否已上架、渠道健康和 Base URL | 模型预检、渠道密钥、上游 `/models`、熔断状态 |
| 费用不一致 | 请求记录和时间范围 | 供应商 usage、平台账本、重试/退款流水 |
| 流式中断 | 网络和请求 ID | 上游超时、是否已发送首字节、渠道切换限制 |
| 兑换失败 | 兑换码有效期、次数和是否重复领取 | 福利码状态、账户兑换历史、审计记录 |

所有异常排查优先使用 Request ID/Trace ID，不要求用户提供密码、完整 API Key 或模型正文。

## 8. 发布签字清单

发布负责人在以下项目全部确认后签字：

- [ ] 真实供应商渠道已配置，密钥未写入 Git。
- [ ] 至少一个文本模型完成真实同步、流式、Token 和成本核验。
- [ ] 余额不足、超时、失败退款、重复请求均有测试证据。
- [ ] 管理员/运营/审计员/用户权限矩阵已复核。
- [ ] 注册、登录、密码重置、LokSystem OIDC、Key 轮换已复核。
- [ ] 额度、订单、退款、福利、账本和对账已复核。
- [ ] PostgreSQL Gate、迁移、备份恢复和预发布 UAT 已通过。
- [ ] 桌面/移动截图和可用性检查已通过。
- [ ] HTTPS、CORS、限流、日志脱敏、告警和回滚方案已就绪。

本手册不能替代供应商合同、支付机构合规要求或生产变更审批。任何“人工确认”“测试密钥”“本机 SSO”都必须在进入生产前替换为正式流程。
