# LokToken 发布阶段实施清单

## 阶段 A：本地开发

- 使用 `.env.example`、SQLite 和本地进程启动；运行 `scripts/release_stage_check.py A`。
- 可启用 Mock 或本地供应商沙盒，验证注册、登录、工作空间、API Key、模型调用、用量和兑换码。
- 支付仅用于联调：个人二维码必须标记为人工确认，不能声称自动到账。

## 阶段 B：小范围内测

- 使用独立测试数据库、真实供应商沙盒或单一真实模型；`TOKEN_MOCK_MODE=false`。
- 通过管理员创建账户或试用链接邀请测试用户；每个测试账户使用独立额度和 API Key。
- 内测支付使用人工二维码时，用户提交付款流水号/备注，管理员在管理台确认或拒绝；拒绝不入账。
- 每次内测发布前执行 `scripts/release_stage_check.py B`、完整 pytest、`/healthz`、`/readyz` 和一次模型预检。

## 阶段 C：公开免费 / 邀请测试

- 使用 HTTPS、公网域名、PostgreSQL、Redis、网关限流、审计日志和备份；执行 `scripts/release_stage_check.py C`。
- 默认免费或邀请额度，不开放自动售卖；试用链接设置有效期、最大领取次数和模型/Key 限额。
- 人工二维码仍只能作为线下审核通道。正式收费前必须接入已实现的微信商户 Native 或其他真实支付适配器，并完成签名、金额、回调幂等、退款和对账验收。
- 发布负责人记录版本、迁移 revision、供应商健康检查、关键 UAT、回滚点和异常联系人。

## 当前 P0 放行标准

注册/登录/登出、密码找回、管理员 RBAC、账户与组织隔离、API Key 一次展示和轮换、余额预扣/结算、订单确认/拒绝/退款、福利兑换、审计、健康检查和就绪检查均必须有测试或验收证据。真实供应商、生产数据库、HTTPS、Redis、备份和真实支付凭证属于部署环境放行条件，不能用本地配置伪造完成。
